## 0. 一页摘要

**现在的位置**

- 当前最好的无角色检测方法：`UX_neff + UUd_share`，NN decoder 的 p 通道（[`three_gaps/exp13_pure_simplicity/`](../../three_gaps/exp13_pure_simplicity/README.md)）。
  - C1–C3：TEST MCC .960–.969，泄漏接近监督 Oracle（两个独立训练的 NP 上都成立）。
  - CR3：MCC .812–.817，泄漏 .165–.183（Oracle：.869–.872，.089–.105）。
- 允许“找角色”的流水线在 CR3 上更好（.83–.86，`three_gaps/exp11_cr3_search/`），但被排除，不作为目标。

**最重要的三个事实**（决定了下面的所有方向）

1. **瓶颈是 NN decoder，不是函数本身，也不是旋转族。** 通用稀疏性损失在 CR3 的**解析函数**上是强信号（Oracle 处 z = 5–8），在 decoder 上降到 −1 到 +1。decoder 梯度 ≈ 0.86 倍真梯度 + 约 0.007–0.01 的各向同性噪声底，二阶结构被扭曲得更厉害。
2. **“Oracle 处信号强”不等于“能被优化找到”。** 一阶软 L0 扣 ×2 噪声底后 Oracle 处 z = 3.0–3.5，但直接优化仍只有 .66–.75。
3. **组合权重是当前方法的软肋。** UX 稀疏单独就让 C1–C3 达到 Oracle，但对 CR3 无偏好（Oracle 处 z = −0.6）；自曲率项帮助 CR3，却会在 C1–C3 的 logit 通道引入噪声。自然尺度权重和 z 分数加权都失败了。

**优先级建议**

| 优先级 | 方向 | 理由 |
|---|---|---|
| P0 | 评估卫生：交叉 NP 选超参、自助法置信区间、诊断“损失错位 vs 优化失败”、统一基准 | 便宜，决定后面所有结论是否可信 |
| P1 | 免调权重的组合：ε-约束（词典序）、精度加权共识 | 直接针对“权重”这个软肋，成本低 |
| P1 | 从源头降低 decoder 噪声：冻结 Z 上的 decoder 集成 / 重拟合，用重复间方差估计噪声底 | 对准根因，且噪声底可以 T-free 估计 |
| P2 | 函数层面（不依赖导数）的复杂度；稀疏代理；观测 choice 路线 | 绕开导数噪声 |
| P3 | 新生成器基准、理论刻画、变换族扩展 | 成本高或回报不确定，但决定“通用性”能否成立 |

## 1. 硬约束与已排除项（避免重复）

**必须遵守**（用户明确要求）

- 损失必须是 **W–Y 简单性**：UX 稀疏性、UU 稀疏性、U 的非线性 / 平滑性等；**不做“找角色”类操作**（检测哪根轴是整体增益 / 平移、按参数含义设计轴的先验、依赖设计标记的格子）；**不用 ICA / 非高斯性**等分布损失。
- **最终成功只能在观测 choice 或 NN 输出的 logit / p / choice 上判定**；解析式 logit / p 只能辅助找指标、做诊断，不计成功。
- T 只在旋转冻结之后用于评价；超参选择若用了 T，必须明确标为“Oracle 调参”，并在未参与选择的数据上确认。
- 汇报时同时给 **泄漏**（非对角 |corr| 的均值 / 最大值）与 MCC，因为是否“干净”是看热图判断的。

**已经试过、不再重复**

| 做法 | 结果 | 出处 |
|---|---|---|
| 广义线性族 GL(d) | CR3 更差（.62） | 03 §5.3 |
| 起点数 6 → 48 | 所有起点收敛到同一点：不是优化问题 | 03 §5.3 |
| 软阶段 A、通道 × 损失组合、聚类格子 | 不稳或无增益 | 03 |
| 自然尺度权重、z 分数加权 | 无效 / 更差 | 04 §3.4 |
| 二阶能量按“块最小特征值”扣底 | decoder 上 z 仍为负 | 04 §7.1 |
| 后验平滑解释 decoder 失真 | 否定（s = 0–1.5 无影响） | 03 §3.1 |
| ICA 类项 | 用户明确不要 | 04 §1 |

## 2. 我们学到的东西（计划的依据）

1. **识别信息的位置**：C1–C3 的识别信息主要在 U–X 混合二阶导的稀疏性（Oracle 处 z = +3 到 +25）。CR3 的识别信息主要在“哪些试次上下文里某根轴为零”这类一阶 / 上下文结构（λ 在只有收益的试次、γ 在概率 0.5 的试次），且这种“精确为零”的结构正是 decoder 的噪声底最容易抹掉的。
2. **decoder 误差的形态**：整体收缩（全局线性映射 ≈ 0.86·I，R² = .851）、加性各向同性噪声底（0.007–0.01）、二阶零结构整体消失（λ、τ 的自曲率占比 0.77 / 0.67，解析应为 0）。
3. **p 通道比 logit 更稳**：C1–C3 的 logit 在重复 2 里 C3 掉到 .827，而 p 通道三个 C 模型都 ≥ .96。一个可检验的解释：p 的 Hessian 含 sigmoid 链式项 σ″(η)∇η∇ηᵀ，使 p 通道的自曲率份额自动带上“梯度能量集中度”的信息；logit 通道在线性模型里的曲率则是 NN 伪影。
4. **Oracle 本身不是干净的上限**：CR3 的监督 Oracle 仍有 .089（重复 1）/ .105（重复 2）的泄漏，最大 .23；线性 OLS（非正交）也只到 .067 / .155。CR3 的信息损失主要是后验收缩噪声（Z→T 近似线性：多项式阶数提高不增加 R²）。所以对 CR3 的合理目标应是“泄漏不超过 Oracle 的约 1.5 倍”，而不是 0。
5. **验证上的薄弱处**：组合是在 CR3 重复 1 的 TEST 指标上选的；只有 2 个训练的 NP；全程是同一个 S1 数据集；二阶矩只用了 300 个被试。

## 3. 大方向

### 方向 A：让 decoder 的函数更干净（针对根因）

**依据**：真实函数在通用损失下是强信号（z 5–8），decoder 把它弄丢了；噪声底是各向同性、可估计的。

- **A1 冻结 Z 上的 decoder 集成 / 重拟合。** 保持 NP 的编码器和 Z 不变，只用观测 choice（允许的 Y）重新训练若干个 decoder（不同种子）。集成平均后的梯度 / Hessian 噪声底按 1/K 下降；**重复之间的方差还能 T-free 地估计噪声底**，取代手工的“×2”倍数。
- **A2 旋转不变的平滑正则。** 用对旋转不变的正则（权重衰减、∥∇ₓ h∥²、∥∇²h∥_F² 的总范数）训练 decoder，不偏向任何轴，却能压低伪影曲率。注意：不能用依赖旋转的稀疏正则（那会把答案写进 decoder）。
- **A3 稀疏 / 低复杂度代理（surrogate）。** 在 decoder 的输出值（仅 W 行上的 NN logit / p）上拟合带旋转不变先验的低阶张量基或核回归，再在代理上量简单性。必须先在解析场上确认代理能保住 z，再看 decoder。
- **风险**：A1 / A2 严格说改变了“冻结网络”这一设定，需要在文档里明确定位为“基于冻结 Z 的新 decoder 估计器”，且仍只使用观测 choice 或 NN 输出；A3 的代理会引入新的偏差。

### 方向 B：更好的损失形式与组合方式（针对权重软肋）

**依据**：UX 稀疏单独在 C1–C3 的谷很尖，在 CR3 上很平；曲率项只在 CR3 有用。需要一种**不靠手调权重**的组合。

- **B1 ε-约束 / 词典序。** 先求 UX 项的最小值，再在 “UX ≤ 最小值 + ε·s” 的近最优集合里最小化曲率。C1–C3 里近最优集合很小，曲率项自动失效；CR3 里近最优集合大，曲率项起作用。
- **B2 精度加权共识。** 每个简单性项各自估计旋转并用自助法给出不确定度，再按精度加权合并（SO(d) 上的加权平均）。有信息的项权重自动高，平的项权重自动低。
- **B3 稳健统计量。** 对被试 / 试次的能量用截尾均值、分位数、Huber 等，降低噪声底和个别被试的影响。
- **B4 更高层级的结构度量。** 三阶 UUX 作用、按上下文细分的 UU 作用；注意 Oracle z 扫描已显示二阶 UU 在 decoder 上被扭曲，需要先过 A 方向的清洗。

### 方向 C：函数层面（不依赖点导数）的复杂度

**依据**：导数是噪声最敏感的量；函数值（NN logit / p 在 W 行上的取值）更稳。

- **C1 稀疏低阶表示的拟合误差。** 在旋转协变的基（等方多项式核）上一次拟合，再对每个旋转精确变换，度量“用 UX 双线性（h ≈ ψ(x) + Σᵢ uᵢφᵢ(x)）加少量交互项能解释多少”的代价；类似 step5 的 WAVE_A，但目标改为“简单性随旋转的变化”。
- **C2 MDL 视角。** 用稀疏表示所需的非零系数数（带噪声阈值）作为复杂度。
- **风险**：CR3 的真函数（τ·F(α,λ,γ,x)，对 α、γ 非线性）在 UX 双线性意义下本来就不简单，可能没有信号；需要先用解析场做 Oracle z 扫描。

### 方向 D：验证与通用性（决定结论能不能成立）

- **D1 评估卫生**：交叉 NP 选超参、自助法置信区间、重复次数 ≥ 5、统一基准。
- **D2 观测 choice 路线**：目前所有 exp13 结果用的是 NN 的 logit / p 自动微分；要补上“NN 输出的值 → sieve → 导数”（Gap3 的 decoder WY）以及“观测 choice → sieve”两条允许的 Y 来源。
- **D3 新生成器基准**：增加 3–5 个新生成器（非线性参数、相关参数、非高斯先验、d = 8、不同刺激设计），冻结方法后只跑一次，检验是否只对这四个生成器有效。
- **D4 新数据集复现**：换种子重生成 S1 并重训 NP。

### 方向 E：理论与变换族

- **E1 识别性分析**：线性参数族中 UX 稀疏性的谷为什么尖（各参数梯度剖面在刺激基上支撑不重叠，Birkhoff 凹性）；CR3 为什么不满足（所有参数作用于所有 X 列）；p 通道的 sigmoid 链式项如何改变曲率项的含义。
- **E2 变换族**：逐轴单调扭曲（概览中的“第三种变换族”）；目前证据显示 Z→T 基本线性，优先级低。
- **E3 Z 维度**：zdim > d 时的维度选择与残余维度的处理（目前只有 zdim = d 的设置）。

## 4. 小方向（可以随时插入的改进）

1. 用全部被试（5000）而不是 300 个算二阶矩，看方差下降多少。
2. 对 `UX_neff` 加上 X 标准化版本（重复 1：CR3 logit .695 → .724）。
3. 曲率项形式：`share` vs `sum`；UX 统计量：neff / l1l2 / quartimax / 软 L0（`tune.py` 已写，扫描未跑完）。
4. Haar 标准化的种子、随机旋转数（200）和起点数（24）的敏感性。
5. 让 UX 项按上下文细分（`UX(i,j,c)`，上下文 = W-only 格子）后再取 neff。
6. 对 p 通道与 logit 通道分别报告，并解释差异（见 §2.3）。
7. 记录“Oracle 处的损失 vs 找到的最优点的损失”，用来区分“损失本身错位”与“优化没找到”。
8. 用 Procrustes 对齐两个 NP 的旋转结果（两个 NP 的 Z 坐标不同），检查**跨 NP 一致性**，作为不用 T 的稳定性指标。
9. 逐轴报告角度误差，而不只是 MCC / 泄漏；记录哪一对轴最容易混（CR3：α–γ、γ–τ）。
10. 把噪声底倍数 ×2 改为 T-free 估计（见 A1 的重复间方差），消除“看着 Oracle 选的倍数”这一处事后选择。

## 5. 具体实验卡片

### E1 · 诊断：损失错位还是优化失败

- **目的**：当前最好方法在 CR3 上差在哪里。
- **方法**：对 `UX_neff + UUd_share` 比较 L(Oracle) 与 L(找到的最优点)；在旋转的李代数上沿各平面画损失曲线，估计找到点与 Oracle 处的 Hessian 特征值（谷的尖锐程度）；逐平面（α–γ、γ–τ…）报告角度误差。
- **决策**：若 L(Oracle) > L(找到点) ⇒ 损失错位，走 B1 / B2 / A；若 L(Oracle) < L(找到点) ⇒ 优化问题，换优化器（黎曼牛顿、更多起点、平面轮换精修）。
- **成本**：几小时。**成功标准**：给出明确的二分判断和各平面的角度误差表。

### E2 · 交叉 NP 选超参

- **方法**：在重复 1 上扫描（`tune.py`：权重 w ∈ {0, 0.25, 0.5, 1, 2, 4, 8}、曲率形式、UX 统计量、X 标准化），重复 2 完全留出；再反过来在重复 2 上选、重复 1 上验证。排名指标：p 通道四个模型的平均“泄漏 − Oracle 泄漏”，同时看 logit 通道和 CR3 单独的 MCC。
- **成功标准**：留出 NP 上的结果不低于冻结配置，且选出的超参在两个方向上一致。
- **风险**：两个 NP 太少，选择仍可能是噪声；应尽量扩到 ≥ 3 个 NP（见 E3）。

### E3 · 稳健性与置信区间

- **方法**：对被试自助重采样（300 → 重采样；以及 5000 全体）、起点种子、Haar 种子；重训 ≥ 3 个新种子的 NP（`np/s3_train.py --repeat N`，顺序执行、4 线程）；输出 MCC / 泄漏的均值 ± 标准差和 95% 区间。
- **成功标准**：C1–C3 的区间宽度 ≤ 0.01（MCC）；CR3 的泄漏区间不覆盖 Oracle。

### E4 · ε-约束（词典序）组合（B1）

- **损失**：`minimize C(Q) subject to U(Q) ≤ U_min + ε·s_U`，其中 U = UX_neff，C = UUd_share，s_U = 随机旋转上的标准差，ε ∈ {0.25, 0.5, 1}。
- **实现**：两阶段——先求 U_min；再最小化 `C(Q) + μ·max(0, U(Q) − U_min − ε s_U)²`（μ 取大并递增）。
- **预期（假设）**：C1–C3 的 UX 谷尖，近最优集合只含真轴附近，曲率项不起作用；CR3 的 UX 谷平，曲率项决定位置。
- **成功标准**：C1–C3（logit 与 p）与 UX 单独的差 ≤ 0.01；CR3 ≥ .82（p）。
- **风险**：ε 本身成了新超参（应在 E2 的交叉 NP 协议下选）。

### E5 · 精度加权共识（B2）

- **方法**：对每个简单性项 k（UX_neff、UUd_share、UX_softL0 …）：在 B = 50 次被试自助样本上分别求最优旋转 R̂ₖᵇ；以参考旋转的对数映射得到李代数向量 ξₖᵇ，估计协方差 Σₖ；合并 ξ̂ = (Σₖ Σₖ⁻¹)⁻¹ Σₖ Σₖ⁻¹ ξ̄ₖ，再 exp 回 SO(d)。
- **成本**：基于矩的搜索约 10 秒一次，K = 4、B = 50 约 2000 秒。
- **预期（假设）**：平的项（UX 在 CR3）协方差大，自动被降权。
- **风险**：矩阵对数在大角度下不稳；需要对称 / 符号 / 排列歧义先对齐。

### E6 · 冻结 Z 上的 decoder 集成（A1，我认为最值得做的根因方案）

- **方法**：从 S5 的冻结 Z 和观测 choice 出发，用与原 decoder 相同的架构（`np/src` 中的解码器）、K ∈ {5, 10} 个不同种子重新训练；加旋转不变的平滑正则（A2）。对每个 decoder 取 g、H_UX、H_UU，做三件事：
  1. 集成平均的场（噪声底 ∝ 1/K）；
  2. 噪声底估计 σ̂² = ½ E[(g_a − g_b)²]（跨 decoder 方差，T-free）；
  3. 在集成场上重做 Oracle z 扫描和 `UX_neff + UUd_share` 的优化。
- **成功标准**：CR3 集成场上一阶软 L0 的 Oracle z ≥ 3（目前 0.2–0.4，扣 ×2 后 3.0–3.5）；MCC ≥ .84。
- **风险**：集成降低的是独立噪声，decoder 的**偏差**（整体收缩、二阶结构被扭曲）可能不变；此时 z 不会升。
- **需要明确标注**：这改变了“冻结网络”的设定，只能算“基于冻结 Z 的新 decoder 估计器”，仍只使用观测 choice 或 NN 输出。

### E7 · 稀疏代理（A3）

- **方法**：只用 decoder 在 W 行上的 logit / p 值，在旋转协变的基（等方多项式核 / Nyström RBF，step5 `joint_bank.py`、`kernel_*` 已有相关实现）上做岭回归，再对每个旋转精确变换、在代理上计算导数能量；先在解析场上检验代理能否保住 z。
- **成功标准**：解析场上 z 保持 ≥ 80%；decoder 场上 CR3 的 z ≥ 3。
- **风险**：代理拟合的光滑性假设可能比 decoder 噪声底更糟。

### E8 · 函数层面复杂度（方向 C）

- **方法**：用 E7 的代理，计算“UX 双线性 + 少量交互项”的拟合残差随旋转的变化；以及稀疏表示的非零系数数（带噪声阈值）。
- **先做**：在 CR3 解析场上做 Oracle z 扫描，没有信号就停。

### E9 · 观测 choice / decoder WY 路线（D2）

- **方法**：把 exp13 的损失接到 `three_gaps/common/sieve.py` 的 WY→sieve 估计器上，分别用 (a) decoder 输出的 logit / p 值、(b) decoder 抽样的 binary、(c) 观测 choice；与自动微分结果对比。
- **目的**：确认方法在“允许的 Y”上同样成立，并量化导数估计误差的影响。

### E10 · 新生成器基准（D3，成本最高、价值最大）

- **新增生成器（建议 3–5 个）**：双曲 / 指数折扣（3 参数，对参数非线性）；漂移扩散类 logistic；相关参数先验（ρ = 0.5）；d = 8 的线性模型；非高斯先验（偏态 / 重尾）；不同刺激设计（含更多点质量 / 更少点质量）。
- **流程**：`np/s1_generate.py` 增加生成器 → S2 预检查 → S3 训练 → S5 提取 Z → EXP00 Oracle → **冻结方法后只跑一次**。
- **成功标准**：新生成器上 MCC 差 Oracle ≤ 0.03（线性族）或泄漏 ≤ 1.5× Oracle（非线性族）。
- **风险**：新生成器的 Oracle 本身可能很差，需要先看 Oracle 再下结论。

### E11 · 统一基准（infrastructure）

- **方法**：新建 `bench/`，定义接口 `loss(cache) -> scalar`，固定协议（四个模型 × ≥ 3 个 NP × 两个通道 × 3 个种子），输出带置信区间的表；把 step5 的 BU3、EXP11 流水线、EXP13 当前最好方法放在同一张表里作为基线。
- **预注册**：`bench/protocol.json`（配置哈希）在跑之前冻结，之后只追加结果。

### E12 · 理论刻画（E1 / E2 方向）

- 推导 UX 稀疏性的谷在“梯度剖面支撑不重叠”时的尖锐度，以及 CR3 为何平；推导 p 通道曲率份额与 sigmoid 链式项的关系，判断是否可以在 logit 通道里用“梯度加权的曲率”得到等价的量，从而让两个通道行为一致。

## 7. 评价协议（防止对现有数据过拟合）

1. **预先固定**：每个候选在跑之前写下损失定义、超参、起点数和评价指标；结果只追加。
2. **选择与验证分离**：超参只在一个 NP 上选，另一个 NP 完全留出；再反向各做一次。
3. **指标**：MCC、泄漏均值 / 最大值、逐轴角度误差、跨 NP 的 Procrustes 一致性、自助法 95% 区间；CR3 的目标写成“泄漏 ≤ 1.5× Oracle”和“MCC ≥ .84”。
4. **标注**：任何用了 T 选超参、看了 Oracle 处数值才决定的量（例如噪声底 ×2），在文档里单独标出“事后选择”。
5. **允许的 Y**：成功只在观测 choice 或 NN 输出的 logit / p / choice 上报告；解析场只用于诊断。

## 8. 开放问题与不做的事

**开放问题**

- CR3 的监督 Oracle 泄漏本身是 .09–.10；比 Oracle 更好的“干净”程度在 CR3 上是否根本不可能（信息损失来自后验收缩）？E6 / E7 的结果可以回答 decoder 去噪后的上限。
- 是否存在一个同时对四个生成器及新生成器都成立的**单一**简单性定义，还是必须依赖通道（p 比 logit 更稳）？
- “纯 W 上下文”（X 列的众数模式）作为格子划分的规则，在刺激设计很不同的任务上是否仍合适？（阈值：众数占比 10%、最小格子 6%、至少 2 个标记，目前只在四个生成器上检验过。）

**不做的事**

- 不再引入新的“找角色”类阶段（增益轴、平移轴、按参数含义的格子）。
- 不用 ICA / 非高斯性。
- 不再试探更多固定权重；若组合不免调，就用 E4 / E5。
- 不在没有预先固定协议的情况下反复在同一个 NP 的 TEST 指标上挑选损失。

## 10. 前三个优先实验的实现细则

> 以下只是实现草案，路径和参数在写代码时可以调整；每个实验都放在自己的独立目录，不改冻结基线（见“本篇的工作规则”）。

### 10.1 E1 诊断（`three_gaps/x6_e01_diagnosis/`）

**输入**：`exp13_pure_simplicity/cache2.py` 生成的缓存（四个模型 × 重复 1 / 2 × p 通道），冻结的 `UX_neff + UUd_share` 配置（Haar 标准化 200 个随机旋转、种子 1）。

**步骤**

1. 用冻结配置求最优旋转 Q_found（24 起点，种子 7）；取监督 Oracle 旋转 R_oracle（`exp00` 保存，只做诊断）。
2. 计算 Δ = (L(R_oracle) − L(Q_found)) / s_L，其中 s_L 为组合损失在随机旋转上的标准差。
3. 对每个坐标平面 (i, j)：把 Givens 角 θ ∈ [−90°, 90°]（步长 1°）分别作用到 Q_found 和 R_oracle，画损失曲线，标出两个旋转处的值。
4. 在 so(d) 坐标里数值估计损失的 Riemannian Hessian（d(d−1)/2 维，中心差分，步长 0.02 rad），报告最小 / 最大特征值与条件数。
5. 逐轴角度误差：匹配后第 k 轴 arccos |⟨q_k, r_k⟩|；并记录哪几对轴（如 α–γ、γ–τ）贡献了主要泄漏。

**输出**：`diagnosis.csv`（模型、重复、L_oracle、L_found、Δ、每轴角度、Hessian 特征值）、每个平面一张损失曲线图。

**判读**：Δ > 1（以 s_L 为单位）⇒ 损失在 Oracle 附近不是极小，属“损失错位”；Δ ≤ 0 ⇒ 优化没找到。Hessian 最小特征值接近 0 的方向就是谷中平坦的方向，应与泄漏最大的轴对一致。

### 10.2 E4 ε-约束（`three_gaps/x6_e04_epsilon/`）

**第一阶段**：用 UX_neff 单项求 24 个起点的最优值 U_min 和对应旋转集合；估计 s_U（200 个 Haar 旋转，种子 1）。
**第二阶段**：对 ε ∈ {0.25, 0.5, 1}（单位 s_U），在罚函数 J(Q) = C(Q)/s_C + μ·max(0, (U(Q) − U_min)/s_U − ε)² 上做延续法（μ = 1, 10, 100, 1000，每个 μ 以上一个 μ 的解为初值），C = UUd_share。
**同时记录**：
- 近最优集合的大小：从第一阶段的最优点出发做随机游走，统计 U ≤ U_min + ε·s_U 的可达角度范围；C1–C3 预期很窄、CR3 预期很宽。
- 与冻结等权基线、UX 单独的三方对照（同数据、同起点预算）。

**输出**：每个 (模型, 通道, 重复, ε) 的 MCC / 泄漏、近最优集合宽度；C1–C3 的 logit 与 p 单独汇总，用来检验“曲率项只在 UX 谷平时起作用”这一假设。

### 10.3 E6 冻结 Z 上的 decoder 集成（`three_gaps/x6_e06_decoder_ensemble/`）

**数据**：S5 的 `s4_evaluate__latent.npz`（每个被试一个冻结 Z）、S1 的刺激和观测 choice；沿用原来的训练 / 验证 / 测试被试划分。
**模型**：与原 NP 解码器相同的结构（`np/src/modlearn_rot/nn/np/point/discrete.py` 中 `_make_decoder`，隐层 (128, 256, 128)），输入 [x, z]、输出两类 logit。
**训练**：对每个被试的所有试次，用固定的 z 做二元交叉熵（只用观测 choice，不用 NN 输出）；K = 10 个种子；权重衰减 1e-4；可选旋转不变的平滑项 λ·E[‖∇_z h‖²_F] 或 λ·E[‖∇²_z h‖²_F]（对 z 做正交变换不变，因此不预先偏向任何轴）；验证被试早停。
**导数**：对每个 decoder 在同一网格（与 cache2 相同的 300 个 TRAIN 被试 × 全部试次）取 g、H_UU、H_UX。
**产出三样**：
1. 集成平均后的场（预期独立噪声按 1/K 下降）；
2. 噪声底的 T-free 估计 σ̂² = ½ E[(g_a − g_b)²]（跨 decoder 方差），取代手工的“×2”；
3. 在集成场上重做 Oracle z 扫描（`exp13_pure_simplicity/oracle_scan.py` 的目录）和冻结的 `UX_neff + UUd_share` 优化。

**注意**：这是“基于冻结 Z 的新 decoder 估计器”，不再是原 NP 的 decoder；它用观测 choice 训练，符合 Y 规则，但在文档里要明确标注与“冻结网络”设定的差别。训练是后验均值 z 而不是采样 z，也可能带来系统差别，需要和原 decoder 的场对照。

## 11. 失败后的决策树

```
E1 诊断
 ├─ Δ > 1（损失错位）
 │    ├─ E4 / E5 能让 CR3 泄漏 ≤ 1.5× Oracle，且 C1–C3 不退化 ──> 采纳，进入 E3 区间与 E10 验证
 │    ├─ E4 / E5 无改善 ──> 损失族本身不够：转 E6（decoder 去噪）或 E8（函数层面）
 │    └─ E6 后 Oracle z 仍低 ──> decoder 偏差（而非噪声）是上限：转 E7（代理）并如实报告 CR3 的可识别边界
 └─ Δ ≤ 0（优化问题）
      ├─ 换优化器（黎曼牛顿、平面轮换精修、更多起点）能找到更低点 ──> 重新评估
      └─ 找不到更低点 ──> 回到“损失错位”分支
```

- 任何一步的结论都要在**留出 NP** 上确认；若只在一个模型、一个种子或事后选权重时成立，不判定为通用成功。
- 若所有方向都不能让 CR3 的泄漏降到 1.5× Oracle 以内，就把结论写成“在 CR3 上无角色检测方法的上限约为 .82，瓶颈是 decoder 偏差”，并给出证据（Oracle z 扫描、E6 集成后的场、解析场对照），而不是继续堆损失。
