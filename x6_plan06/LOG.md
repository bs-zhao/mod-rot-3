# x6_plan06 实验日志（倒序，最新在上）

## 2026-11-14 · E4 ε-约束（词典序）组合：不优于冻结等权基线

**做了什么**：第一阶段求 UX_neff 单项的最优值 U_min；第二阶段在 UX_neff ≤ U_min + ε·s_U 的约束下最小化 UUd_share（罚函数延续法，μ = 1 / 10 / 100 / 1000，12 个起点：6 个来自第一阶段、6 个随机），ε ∈ {0.25, 0.5, 1.0}（单位为 Haar 标准差）。4 个模型 × 重复 1 / 2 × p / logit 共 16 个设置。同时测量 UX_neff 离开最优点时的上升速度（5° / 20° / 45° 随机方向的中位增量，单位 s_U）。
代码：`e04_epsilon/run.py`；结果：`e04_epsilon/results/epsilon_constraint.csv`、`summary_by_group.csv`、`e04.log`、各 Q 矩阵 `.npy`。

**结果**（TEST，MCC / 泄漏，组内平均；括号内为 C1–C3 三个模型两个重复的平均）

| 通道 | 组 | 冻结等权基线 | UX 单独 | ε = 0.25 | ε = 0.5 | ε = 1.0 |
|---|---|---|---|---|---|---|
| p | CR3 | **.815 / .174** | .731 / .242 | .787 / .194 | .799 / .186 | .763 / .218 |
| p | C1–C3 | .965 / .040 | .966 / .034 | .962 / .051 | .959 / .060 | .954 / .069 |
| logit | CR3 | **.820 / .175** | .709 / .250 | .802 / .187 | .813 / .172 | .723 / .244 |
| logit | C1–C3 | .904 / .129 | **.967 / .031** | .939 / .086 | .916 / .116 | .881 / .156 |

UX_neff 离开最优点的上升（s_U 单位，中位）：20° 处 CR3 0.41、C1–C3 0.59；45° 处 CR3 1.94、C1–C3 2.47。

**结论**
1. **ε-约束没有优于冻结的等权基线**：CR3 上所有 ε 都低于基线（p：.787–.799 对 .815；logit：.802–.813 对 .820，ε = 0.5 的 logit 基本持平）；C1–C3 的 p 通道略低于基线（.954–.962 对 .965）。
2. **在 logit 通道的 C1–C3 上它确实好于等权基线**（ε = 0.25：.939 对 .904），但仍明显不如 UX 单独（.967），说明只要允许曲率项在近最优集合里起作用，就会把 C 模型推离真轴。
3. **假设没有得到支持**：预期 “C1–C3 的 UX 谷尖、CR3 的谷平”，实测上升速度只有约 1.4 倍的差别（20° 处 0.59 对 0.41 个标准差）；不存在一个 ε 能同时让 CR3 受益（需要较大的 ε）又让 C1–C3 不受害（需要小的 ε）。
4. **不采纳 E4**。冻结基线继续作为推荐方案。

**限制**：只用了一个起点预算（12）和 ε 的三个取值；UX 的谷宽度用随机方向的中位增量近似，没有做更细的角度扫描；Q 搜索的罚函数延续参数没有调。

## 2026-11-14 · E1 诊断：损失错位而不是优化失败

**做了什么**：对 4 个模型 × 重复 1 / 2 × p / logit 共 16 个设置，用冻结的 EXP13 配置（`UX_neff + UUd_share`，Haar 标准化 200 个旋转种子 1，24 起点种子 7）求 Q_found（基线复现：CR3 p 重复 1 为 .817 / .165 / .368，与冻结结果一致）。再把监督 Oracle 旋转 R_oracle 仅作诊断，比较两处损失（双精度），画各平面的损失曲线，用中心差分（步长 0.02 rad）估计 so(d) 坐标下的 Hessian 和梯度，并计算逐轴角度误差。
代码：`e01_diagnosis/run.py`；结果：`e01_diagnosis/results/diagnosis.csv`、`planes_CR3_prob_rep{1,2}.png`、`e01.log`。

**结果**（Δ = (L(R_oracle) − L(Q_found)) / Haar 标准差）

| 通道 | 模型 | 重复 | MCC / 泄漏 | Δ（sd） | 最大轴角度误差 | 找到点 Hessian 最小 / 最大 | Oracle 处 Hessian 最小 / 梯度范数 |
|---|---|---|---|---|---|---|---|
| p | CR3 | 1 | .817 / .165 | **+2.64** | 26.2° | 1.80 / 24.9 | **−6.17** / 5.85 |
| p | CR3 | 2 | .812 / .183 | **+2.31** | 28.9° | 1.85 / 19.2 | **−6.74** / 5.32 |
| p | C1 | 1 / 2 | .969 / .021, .969 / .020 | +0.01 / +0.02 | 1.9° / 2.3° | 22.9 / 26.8 | 22.9 / 0.9–1.5 |
| p | C2 | 1 / 2 | .965 / .060, .968 / .043 | +0.09 / +0.08 | 8.0° / 5.5° | 5.8 / 7.2 | 5.8 / 2.5–2.7 |
| p | C3 | 1 / 2 | .960 / .046, .962 / .048 | +0.12 / +0.08 | 5.8° / 7.1° | 4.0 / 2.4 | 3.9 / 2.0–2.7 |
| logit | CR3 | 1 / 2 | .831 / .160, .810 / .191 | +2.11 / +1.79 | 20.5° / 26.9° | 0.84 / 0.91 | −5.2 / −3.2 |
| logit | C1 | 1 / 2 | .925 / .132, .947 / .098 | +0.62 / +0.41 | 22.5° / 16.5° | 6.4 / 6.1 | 0.65 / 7.4 |
| logit | C2 | 1 / 2 | .912 / .136, .897 / .141 | +0.56 / +0.41 | 28.0° / 31.9° | 5.0 / 1.1 | 1.4 / −1.7 |
| logit | C3 | 1 / 2 | .919 / .107, .827 / .161 | +0.80 / +1.36 | 26.0° / 51.9° | 1.3 / 2.0 | −1.2 / −7.1 |

**结论**
1. **所有设置里 Δ ≥ 0**：Oracle 处的损失从不低于找到点的损失，所以**不是优化没找到**，而是损失本身在 Oracle 处不是极小（“损失错位”）。
2. **CR3 p**：错位约 2.3–2.6 个标准差；找到点是尖锐的局部极小（Hessian 全为正，最小 1.8），Oracle 处则不是驻点（梯度范数约 5–6，且存在负曲率约 −6）。轴角度误差 26–29°。
3. **C1–C3 p**：Δ ≈ 0（≤ 0.12 sd），Oracle 就在损失谷里（Hessian 全为正，梯度小）。
4. **C1–C3 logit**：Δ = +0.4 到 +1.4 sd，Oracle 处出现负曲率（C2 / C3），角度误差最大 52°：曲率项在这些线性模型上引入的伪结构把极小推离真轴，这正是 logit 通道不稳的原因。

**决策（按文档 06 决策树）**：Δ > 1 的分支 ⇒ 损失错位 ⇒ 下一步 E4（ε-约束）与 E5（精度加权共识），再 E6（decoder 去噪）。同时 E2 的交叉 NP 选超参可并行。

**限制**：Hessian 是在 so(d) 坐标用中心差分估计的，Oracle 处不是驻点，其特征值只反映局部曲率，不是严格的 Riemannian Hessian；仅在已缓存的 300 个 TRAIN 被试网格上计算。
